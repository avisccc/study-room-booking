# 1. 簡介

## 1.1 文件目的

本軟體需求規格書（SRS）描述「討論室預約系統」應提供的功能、操作限制、外部介面、非功能性品質要求與可驗收的業務結果，供瀑布組需求審查、簽核、後續 UML 設計、程式實作及系統測試使用。規格依據 2026/11/05 的共用需求來源清單與共同假設；每項 FR 標記對應 SRC 來源編號，方便需求追溯。

## 1.2 產品範圍（Product scope）

本系統為電腦與手機瀏覽器均可操作的網頁應用。學生可查詢空閒討論室、建立及管理預約、邀請其他學生、申請候補、查詢使用紀錄與違規點數。館員可管理房間和開放時間、查看預約、執行報到及違規處理。系統使用 Mock Mail Adapter 模擬通知，並提供獨立虛擬設備介面展示討論室的控制互動。

## 1.3 產品價值（Product value）

系統擬改善下列使用情境：

| 問題 | 對應改善方向 |
|---|---|
| 不知道哪間討論室有空 | 提供依房間、時段、設備、容量查詢的空閒狀態。 |
| 已預約卻未到場占用時段 | 以報到、逾期未到場、記點和停權規則管理。 |
| 單一學生占用過多時段 | 依有效預約的每日時數及筆數限制管理。 |
| 館員仰賴人工資料管理 | 統一房間、預約、違規及操作紀錄。 |

上述為產品目標，不表示已設定或保證量化成效指標。

## 1.4 目標使用者與使用方式（Intended audience / use）

| 使用者 | 操作內容 | 身分限制 |
|---|---|---|
| 學生 | 以已建檔學號進入學生端，查詢、預約、邀請、候補、點數及虛擬設備。 | 無密碼正式登入；只可操作本人有權存取的資料。 |
| 館員 | 以共用館員身分進入管理端，管理房間和開放時間、報到、違規與通知。 | 不建立個別館員帳號，成功管理操作須可稽核。 |

## 1.5 功能邊界

本專案涵蓋 F01 身分與操作範圍、F02 討論室查詢與管理、F03 一般預約與共用規則、F04 多人邀請、F05 候補、F06 報到及完成、F07 點數及停權、F08 模擬通知、F09 虛擬設備，及 G 跨功能處理規則。

**不納入：** 真實帳號密碼認證、真實 Email 寄送、背景排程／定時工作、真實硬體控制。共用來源未規定固定房間數、同時使用者量、反應時間或實體設備協定，本版不另行假設。

## 1.6 基本術語及時間基準

| 術語 | 意義 |
|---|---|
| **預約者** | 一筆預約唯一的負責學生；預約額度、報到責任與未到場點數都歸屬此人。 |
| **受邀者／參與者** | 受邀者尚可接受或拒絕；接受後成為參與者。參與者不分擔預約者的時數、筆數及未到場記點。 |
| **待確認** | 含受邀者且尚未全員接受的預約申請；不占用房間或預約額度。 |
| **有效預約** | 已成立且狀態為「已預約」或「已報到」、尚未結束的預約；占用房間時段及預約者額度。 |
| **候補申請** | 針對特定討論室與起訖時間提出的等候資格；與已成立預約的狀態分開表示，候補中不占用房間或額度。可保留已確認的多人參與名單。 |
| **事件觸發更新** | 不依賴背景排程；僅在與對應業務相關的查詢或操作時，檢查並更新其涉及的到期狀態／通知。 |
| **時間基準** | 所有業務日期、整點、日界與提醒視窗均以 `Asia/Taipei` 解讀；是否到期以系統伺服器當下時間判斷。 |

## 2.3 外部介面需求（External interface requirements）

### 2.3.1 使用者介面（User interface）

系統應呈現學生端及館員端對應的功能，並提供身分選擇入口。學生介面應能查房、管理自己的預約／邀請／候補及點數；館員介面應能管理房間／開放時間、查詢預約、報到、處理點數與通知。公開空閒時段不得揭露其他學生私人資料，且需支援電腦和手機瀏覽器的主要操作（SRC-02、SRC-50）。本版不規定特定畫面配置與元件樣式。

### 2.3.2 硬體介面（Hardware interface）

本系統不控制真實硬體。系統提供獨立虛擬設備介面，模擬討論室門禁、燈具、空調或電源等可選控制項；設備類型及控制協定不強制固定。介面應可觀察主系統傳入的控制動作和對應設備狀態（SRC-45～47）。

### 2.3.3 軟體與資料介面（Software interface）

以 TypeScript、Next.js、Tailwind CSS 建置網頁，使用 PostgreSQL（Neon）與 Prisma 保存資料，部署於 Vercel。兩組系統與資料庫獨立；具體資料表設計、函式與 API 路徑屬於後續設計，不自行寫成 SRS 要求。

### 2.3.4 通訊介面（Communication interface）

Mock Mail Adapter 需記錄通知收件者、內容、待寄送／成功／失敗狀態及重試紀錄，但不實際寄送 Email。主要預約系統與獨立虛擬設備介面之間應具備可觀察的控制請求與結果；通訊技術與協定由設計階段決定（SRC-41～47）。

## 2.4 系統約束與事件時機

所有日期、日界、整點及提醒時間視窗依 `Asia/Taipei` 解讀；到期以伺服器當下時間為準。**不使用背景排程**。需在具業務因果關聯的查詢或操作中，按第 5.5 節事件表處理相關預約、點數、候補、提醒及設備狀態，不因無關頁面存取而掃描全站（SRC-48）。

## 2.5 需求識別與審查基準

- `FR-01`～`FR-49` 對應 `SRC-01`～`SRC-49`，每條記錄規格與驗收重點。
- `SRC-50`～`SRC-52` 歸入第 4 章非功能需求；SRC-02、SRC-48、SRC-49 另以跨功能 NFR 角度重述品質與驗收要求，不引入新的業務規則。
- 第 5 章集中列出業務約束和狀態轉換，供建模與測試對照，不另創不同數值。
- 本稿為 v0.1。依專案計畫，先由 B 確認草稿完整，再經 B（主審）、C（次審）兩輪正式審查及 B 簽核，形成 v1.0。簽核後需求異動走 `change-request` 與重新簽核程序。

# 3. 功能需求（Functional requirements）

每條需求都有唯一 `FR-xx`、明確 `SRC-xx` 來源與驗收條件。規格採用共同需求文件的原始敘述，以避免改寫造成限制、邊界或狀態語意偏差。下列內容尚待人工審查、核准。

## 3.1 F01｜身分與操作範圍

學生與館員透過簡化身分選擇執行對應操作，私人資訊依選用身分隔離。

### FR-01 身分選擇

- **來源**：SRC-01
- **功能規格**：使用者可輸入**已建檔學號**選擇學生身分，或選用**共用館員身分**；可返回入口重新選擇。無密碼及正式身分驗證。
- **驗收條件**：未建檔學號不可進入學生端；不同角色顯示對應功能，切換後依新選用身分操作。

### FR-02 操作權限

- **來源**：SRC-02
- **功能規格**：學生只能查看／處理其目前身分所屬的預約、邀請、候補、點數及停權資訊；能對邀請做出回覆，但不能替其他預約者修改或取消預約。館員可查看預約與違規資料並執行館員管理事項。
- **驗收條件**：不得以學生端讀取或修改無關學生的私人資料；公開空閒時段不揭露其他學生個資；不只隱藏按鈕，也要拒絕未授權操作。

## 3.2 F02｜討論室查詢與館員管理

房間資訊、條件搜尋、開放時間及館員預約查詢。

### FR-03 房間與時段查詢

- **來源**：SRC-03
- **功能規格**：學生可查看可用討論室、開放時間及依日期、起訖時段查詢使用狀況。
- **驗收條件**：可區分指定時段可預約與不可預約；已停用房間不得提供新預約。

### FR-04 條件搜尋

- **來源**：SRC-04
- **功能規格**：學生可依房間固定設備標籤、容納人數，結合日期／時段尋找符合條件的討論室。
- **驗收條件**：結果符合所選標籤、容量及時段條件，不把不可使用的房間列為可預約。

### FR-05 房間管理

- **來源**：SRC-05
- **功能規格**：館員可新增、修改及停用討論室，管理名稱、固定設備標籤與**正整數**容量；不得刪除歷史預約。有尚未結束的有效預約時不能停用；縮小容量若不足容納任何既有有效預約的預約者與參與者，須拒絕。
- **驗收條件**：有效預約不因房間管理而被破壞；待確認申請不阻止修改，但最終成立時須依最新容量與房間狀態重驗；館員能查看停用房間歷史。

### FR-06 開放時間管理

- **來源**：SRC-06
- **功能規格**：館員可設定或修改各房間開放時間。預約成立／修改後必須完整落在對應房間的開放時間內；若變更會使既有有效預約不受涵蓋，須拒絕。
- **驗收條件**：更改開放時間不破壞有效預約；尚未成立的待確認／候補在成立時依最新規則驗證。

### FR-07 館員查詢預約

- **來源**：SRC-07
- **功能規格**：館員可依日期、討論室或時段查看預約者、參與者及預約狀態，包含當日／即將開始及使用中的預約資訊。
- **驗收條件**：查詢內容正確，並依 SRC-48 對**查詢範圍內相關預約**處理到期狀態或提醒，不影響無關房間與日期。

## 3.3 F03｜一般預約與共用規則

建立、修改、取消與額度限制；多人預約和候補成立均引用同一規則。

### FR-08 建立預約

- **來源**：SRC-08
- **功能規格**：學生指定討論室、開始與結束時間，並可選擇邀請其他學生。**無受邀者**且通過共用預約規則者直接成為「已預約」；有受邀者依 F04 處理。房間時段衝突時可依 F05 選擇候補。每筆正式成立的預約恰有一位預約者。
- **驗收條件**：不符合規則者不得直接占用時段；成立後可查到正確房間、時間、預約者與狀態。

### FR-09 我的紀錄

- **來源**：SRC-09
- **功能規格**：學生可查詢自己作為預約者、受邀者或參與者的相關預約與邀請，及自己提出的候補狀態；至少呈現房間、時間、參與名單與狀態。
- **驗收條件**：歷史資料保留且可依目前選用身分查詢；不顯示無關學生的私人紀錄。

### FR-10 修改預約

- **來源**：SRC-10
- **功能規格**：只有預約者可修改**已預約**的討論室、開始或結束時間，參與名單不變；**待確認**不可直接修改，須取消並重新建立。修改須符合 SRC-18 並依新內容重驗所有適用規則；計算自身額度時排除原預約。**修改不觸發候補遞補，候補名單也不因個別預約修改而重建**（以討論室為單位，見 F05）。
- **驗收條件**：修改成功後資料及通知一致；不符合條件時原預約維持不變；不會錯誤清除其他學生的房間候補。

### FR-11 取消預約

- **來源**：SRC-11
- **功能規格**：只有預約者可取消自己的「待確認」或「已預約」預約，取消後保留歷史且不可復原。待確認可於開始前取消；已預約須符合 SRC-18。**待確認被預約者取消時，所有受邀者均收到取消通知**，未回覆邀請即結束；已預約整筆取消才依 F05 檢查候補。
- **驗收條件**：取消後狀態正確、沒有部分取消；所有受邀者均有對應待寄送通知，已接受者也包含在內；只有符合條件的已預約取消會啟動遞補。

### FR-12 整點與時長

- **來源**：SRC-12
- **功能規格**：開始、結束時間**均須為整點**，每筆時長限 **1、2、3 或 4 小時**，不可為小數小時或超過 4 小時。
- **驗收條件**：如 10:00–11:00、10:00–14:00 合法；10:30–11:30、10:00–11:30、10:00–15:00 拒絕。

### FR-13 每日時數

- **來源**：SRC-13
- **功能規格**：每位學生以**預約者**身分持有的有效預約，按 `Asia/Taipei` 每個當地日期各自計算，不得超過 **8 小時／日**；跨午夜按各日實際占用時數拆分，參與他人預約不占自己的額度。
- **驗收條件**：新增、修改與成立時，各受影響日期都不超標；修改不重複計算原預約。

### FR-14 有效筆數

- **來源**：SRC-14
- **功能規格**：每位預約者最多同時持有 **10 筆**有效預約；待確認、候補中及參與他人預約均不計入。
- **驗收條件**：已有 10 筆時第 11 筆不得成立；修改既有一筆不算新增。

### FR-15 房間衝突

- **來源**：SRC-15
- **功能規格**：同房間有效預約的時間不可重疊；時間視為**左閉右開區間**，前筆結束時間等於後筆開始時間不衝突。**不同房間的重疊預約允許同一學生持有**，仍受其他額度限制。
- **驗收條件**：同房同時段競爭最多一筆成功且不可留下部分結果；不同房間同時段不因「同一學生」而直接拒絕。

### FR-16 停權資格

- **來源**：SRC-16
- **功能規格**：停權中的學生不可作為預約者使新預約成立或遞補；可接受他人邀請並作為參與者。既有已成立預約仍可查看；參與者不取得取消、修改、報到責任或設備啟用權。
- **驗收條件**：成立／遞補時檢查最新停權狀態；不把停權錯誤套用到受邀者的接受資格。

### FR-17 時間與房間有效性

- **來源**：SRC-17
- **功能規格**：開始須**晚於當下伺服器時間**，結束晚於開始；房間可用，且整段預約位於開放時間內。
- **驗收條件**：不接受已到達或過去的開始時間；跨日依相關日期的開放時間完整檢查。

### FR-18 修改與取消期限

- **來源**：SRC-18
- **功能規格**：「已預約」僅可在距**原開始時間至少 3 小時**時修改或取消；修改後新開始時間也須距現在至少 3 小時。待確認僅可在開始前取消。
- **驗收條件**：恰好 3 小時允許已預約修改／取消，少於 3 小時拒絕；已開始者不能修改／取消。

### FR-19 額度與占用定義

- **來源**：SRC-19
- **功能規格**：只有尚未結束的「已預約」／「已報到」屬有效預約，占用房間時段及預約者的 SRC-13／14 額度。「待確認」、「已取消」、「已完成」、「未到場」及候補中不占用。
- **驗收條件**：評估空房與額度前，僅處理本次查詢／操作相關的到期狀態（SRC-48）；狀態變更後不殘留錯誤占用。

### FR-20 預約狀態

- **來源**：SRC-20
- **功能規格**：正式預約／邀請申請的狀態限：「**待確認、已預約、已報到、已取消、已完成、未到場**」。每筆同時只有一種狀態，保留變動時間與原因；允許的轉換見第 12 節。**候補狀態另由 F05 管理，不額外混入此六種預約狀態**。
- **驗收條件**：不可無故跳轉、重複報到或復原已取消預約；相關記錄能反映歷史。

## 3.4 F04｜多人預約與邀請

全員接受後才進入成立檢查，區分預約者與參與者責任。

### FR-21 發送邀請

- **來源**：SRC-21
- **功能規格**：預約者可透過已建檔學生的**學號或 Email** 邀請他人；不得邀請自己或重複邀請同一學生。建立前核對受邀者存在、房間、時段、預約者停權資格及容量；成功後建立邀請及通知。可在提出時一併表達衝突時是否願意候補。
- **驗收條件**：受邀名單無重複；有有效邀請及收件記錄；尚未全員回覆不直接占房。

### FR-22 待確認階段

- **來源**：SRC-22
- **功能規格**：含受邀者的申請在全部接受前狀態為「待確認」，參與名單與房間／時段固定、不直接編修，且不占有效額度及房間。若到達預約開始仍未全員確認，於相關事件觸發時取消申請、結束邀請並通知。
- **驗收條件**：未回覆時不可誤判已成立；過期後不可再接受或成立。

### FR-23 接受與成立

- **來源**：SRC-23
- **功能規格**：每位受邀者可在開始前接受自己的未回覆邀請，一次有效回覆不得重複。全員接受後，依最新房間、容量、時間、預約者停權與 F03 共用規則檢查：**可預約則成立**；**僅房間時段衝突且已同意候補則轉入 F05**；其他不符合條件或未同意候補者取消申請，保留原因並通知。
- **驗收條件**：只剩一人未回覆仍不成立；全部接受後不能同時產生正式預約與候補；轉候補不占房，後續遞補保留已接受的參與名單。

### FR-24 拒絕與取消

- **來源**：SRC-24
- **功能規格**：任何受邀者在待確認時拒絕，整筆申請即取消；尚未回覆邀請一併結束，記錄拒絕者、時間與原因並通知相關人。預約者主動取消待確認者按 SRC-11。
- **驗收條件**：被取消的邀請不得再接受；不產生有效預約或候補。

### FR-25 人數與容量

- **來源**：SRC-25
- **功能規格**：預約者加上全部**不重複受邀者**不得超過房間正整數容量；建立邀請時先檢查，全員接受／候補成功遞補時依最新容量重驗。
- **驗收條件**：超額邀請立即拒絕；容量後來不足不得成立／遞補；已成立預約受 SRC-05 保護。

## 3.5 F05｜候補與自動遞補

每房間候補名單依加入順序處理，不裁切原申請時段。

### FR-26 候補申請

- **來源**：SRC-26
- **功能規格**：當指定房間與時段和至少一筆**有效預約**實際重疊時，學生可選擇提出候補，也可放棄。申請記錄其房間、完整起訖時間、預約者、參與名單與加入時間；候補中不占房間、每日時數或有效筆數。
- **驗收條件**：只有實際正長度重疊才可加入；與相鄰時段僅接觸端點不算衝突；候補時段仍須符合整點、1～4 小時、未來時間及開放時間。

### FR-27 多人候補

- **來源**：SRC-27
- **功能規格**：**多人預約可以候補，但必須所有受邀者都已接受後才正式排入候補名單。** 發起時可預先選擇願意候補；待確認期間只保留邀請申請、不建立候補資格。全員接受時若只有房間衝突，將待確認申請結案為「已取消（轉候補）」並建立帶有**同一預約者與已接受參與者**的候補申請；若直接有空房則成立預約。
- **驗收條件**：任一邀請未回覆／拒絕都不加入候補；轉候補後不占房，受邀者確認結果保留；遞補成功時不得把多人候補變成單人預約。

### FR-28 名單與順序

- **來源**：SRC-28
- **功能規格**：每間討論室共用候補名單，依加入時間先後處理，不綁定某筆原始預約。不同申請可有不同完整起訖時間；同一預約者不可重複加入**同房間、相同起訖時間**的候補。
- **驗收條件**：名單與時間、成員可查；修改其他人的預約不會重建或清空該房候補名單。

### FR-29 候補退出

- **來源**：SRC-29
- **功能規格**：候補預約者可在遞補前退出自己的候補申請；退出後不再參與遞補，保留候補歷史。
- **驗收條件**：不允許替別人退出；狀態為「已退出」且不占房間／額度。

### FR-30 取消觸發遞補

- **來源**：SRC-30
- **功能規格**：**同房間任一筆「已預約」正式預約整筆成功取消**時，依加入順序依序檢查每一筆候補：其**完整時段**須完全空閒，預約者與全部既定參與者須符合 F03、F04 的適用限制。每成功一筆即產生一筆新的「已預約」，並以最新占用狀況繼續檢查後續候補；**同一次取消可遞補多筆彼此不衝突的候補**。不得裁切候補時段。
- **驗收條件**：依序、整段、逐筆重驗；單人候補生成單人預約，多人候補保留已接受參與者；一次取消可能有零筆、一筆或多筆成功，不產生雙重占用。

### FR-31 遞補失敗與結案

- **來源**：SRC-31
- **功能規格**：遞補時因房間仍衝突、預約者停權、額度或其他暫時不符條件者，記錄原因、跳過並**保留候補中**，供下次相關取消事件重試；開始時間已到、主動退出或成功遞補者則結案，狀態分別為「已失效」、「已退出」、「已遞補」。**原預約修改、未到場、正常完成或館員提前結束均不觸發遞補**。
- **驗收條件**：一人失敗不阻止後續者；過期者不再遞補；候補結果有可查狀態與原因，成功者不重複成立。

## 3.6 F06｜報到與使用結束

報到、逾期未到場及完成使用的狀態變更。

### FR-32 報到

- **來源**：SRC-32
- **功能規格**：館員可在預約開始起至**開始後 10 分鐘（含）**，確認預約者本人到場，替一筆「已預約」辦理**一次**報到，狀態改為「已報到」並記錄時間。參與者是否到場不影響報到，但不能代替預約者。
- **驗收條件**：恰好 +10 分鐘可報到；開始前、超過 +10 分鐘、只有參與者到場或已報到時不得再報到。

### FR-33 未到場

- **來源**：SRC-33
- **功能規格**：「已預約」且超過開始後 **10 分鐘**仍未報到，於相關業務查詢或操作時標為「未到場」，並由 F07 對**預約者**記點一次。
- **驗收條件**：恰好 +10 分鐘不判未到場，超過才判定；不得重複記點；此事件與記點結果一致。

### FR-34 完成使用

- **來源**：SRC-34
- **功能規格**：館員可替已報到的預約提前結束；或於預約到達結束時間後，由相關查詢／操作觸發完成處理。狀態變為「已完成」，並依 F09 關閉設備。
- **驗收條件**：正常到期與提前結束均只完成一次；完成後不得再啟用設備。

## 3.7 F07｜點數、違規與停權

查詢、手動調整、自動恢復與停權期限。

### FR-35 我的點數

- **來源**：SRC-35
- **功能規格**：學生可查看自己的目前有效點數與停權狀態；停權時顯示結束時間。
- **驗收條件**：相關查詢先依 SRC-48 補算本人應恢復的點數及到期停權，顯示與最新結果一致。

### FR-36 館員違規處理

- **來源**：SRC-36
- **功能規格**：館員可查看未到場紀錄、點數與停權，並**以整數**手動加點或減點，必須提供原因。每次異動保存調整前後點數、差額、時間及原因；減點不得超過現有點數，也不能低於零。減點依 SRC-40 抵銷最早尚有效點數，並按 SRC-39 更新停權。
- **驗收條件**：正確記錄可追蹤異動；加點／減點及停權結果同步一致；不合法減點拒絕。

### FR-37 未到場記點

- **來源**：SRC-37
- **功能規格**：每筆預約判定未到場時，只有**預約者增加 1 點**；參與者不記點。每個新增點數保留發生時間，採實際處理事件的伺服器時間而非回填截止時間。
- **驗收條件**：同一筆未到場只加一次；失敗不得只改狀態或只加點。

### FR-38 停權啟動

- **來源**：SRC-38
- **功能規格**：新增點數事件（未到場或館員加點）使目前點數達 **3 點以上**且當下未停權時，啟動一筆新的 **7 天停權**並記錄起訖及原因；僅查詢既有 3 點以上而沒有新加點，不得重新啟動。
- **驗收條件**：2→3 點啟動；已過期且分數仍為 3 點時，純查詢不重啟。

### FR-39 停權更新／解除

- **來源**：SRC-39
- **功能規格**：停權期間新加點且更新後仍達 3 點時，結束時間延至**既有期限與此次加點後 7 天之較晚者**；館員手動減點至低於 3 點可立即提前解禁。到期即解除；**自動恢復點數不提前結束現有停權**。
- **驗收條件**：期間加點延長不縮短；手動減點與自然到期結果不同，不能混淆。

### FR-40 點數自動恢復

- **來源**：SRC-40
- **功能規格**：未到場及館員加點按**每 1 點一筆**保存；每隔至少 **7 天**最多自動抵銷最早未抵銷的 **1 點**。下次恢復時間為「最早未抵銷記點時間＋7 天」與「前次自動恢復時間＋7 天」的較晚者（沒有前次時只用第一項）；手動減點採 FIFO。相關操作時補算所有已到期恢復；清零後新記點重新起算。
- **驗收條件**：不會在不足 7 天間隔內連續自動扣兩點；點數不低於零；先舊後新，且能測試累積到期補算。

## 3.8 F08｜通知與提醒

事件通知、時間提醒、Mock Mail 與去重。

### FR-41 事件通知

- **來源**：SRC-41
- **功能規格**：系統應為下表所列的實際業務事件建立通知，收件人及訊息類型依事件決定；事件發生與通知建立一致記錄。邀請在系統介面接受／拒絕，Mail 僅用來告知，不能透過回信直接操作預約。
- **驗收條件**：相關事件有正確收件人及通知內容；同一次全員接受不因「邀請確認完成」與「預約成立」重複發成功通知。

### FR-42 開始／結束提醒

- **來源**：SRC-42
- **功能規格**：**提醒僅寄給該筆預約的預約者**。館員查詢「接下來／即將開始的預約」時，對**已預約、尚未開始且距開始 ≤30 分鐘**者產生開始提醒並嘗試寄送；館員查詢「使用中／即將結束」時，對**已預約或已報到、尚未結束且距結束 ≤10 分鐘**者產生結束提醒並嘗試寄送。相同預約每種提醒最多一次，修改時間後不重發同種類提醒。
- **驗收條件**：恰好 30／10 分鐘符合；已開始不寄開始提醒、已結束不寄結束提醒；受邀者／參與者不收到這兩種提醒；無關頁面不觸發。

### FR-43 模擬寄送與重試

- **來源**：SRC-43
- **功能規格**：使用 `sources/assumptions.md` 的 Mock Mail Adapter 保留「待寄送、成功、失敗」狀態及收件者、事件、類型、建立／嘗試時間、失敗原因。事件發生的相關操作應嘗試模擬寄送；館員另可主動處理待寄送與失敗通知並重試，**成功者不再寄送**。Mock 失敗不回退已成功的預約、邀請、候補、點數或設備操作。
- **驗收條件**：可展示成功、失敗、重試；通知結果與核心業務結果互不混淆。

### FR-44 通知去重

- **來源**：SRC-44
- **功能規格**：對**同一業務事件＋通知類型＋收件者**不得建立或成功寄送重複通知；不同事件（如兩次手動加點）仍可各自通知。
- **驗收條件**：重複觸發相關查詢不寄出第二封同提醒；失敗重試使用原紀錄而非新增第二份通知。

## 3.9 F09｜智慧控制與虛擬設備

主系統與獨立虛擬設備的啟用及關閉同步。

### FR-45 虛擬設備介面

- **來源**：SRC-45
- **功能規格**：提供與主要預約系統**可互動、可通訊**的獨立虛擬控制介面，代表討論室的**門禁、燈具、空調或電源等設備**。介面能呈現對應房間與設備的目前狀態、收到的控制動作及結果；兩組可自行選擇內部通訊方式與呈現方式，不需要真實硬體。
- **驗收條件**：從主要預約系統發出操作後，虛擬介面反映該房間相應設備的控制結果；可觀察狀態而非僅在預約頁上顯示一段成功文字。

### FR-46 啟用控制

- **來源**：SRC-46
- **功能規格**：只有**已報到**預約的預約者可在其有效使用期間透過主要系統要求啟用對應房間虛擬設備；其他參與者或尚未報到、取消、完成、未到場的預約不得啟用。
- **驗收條件**：有權操作時能對虛擬介面送出啟用並顯示狀態；無權／無效狀態操作拒絕，不會改變設備。

### FR-47 結束關閉

- **來源**：SRC-47
- **功能規格**：預約完成（到期或館員提前結束）或判定未到場時，主要系統應使對應房間虛擬設備處於**關閉／停用**狀態並保留觸發原因與時間；同一狀態無須重複轉換。
- **驗收條件**：設備不在預約結束後保持啟用；可核對主系統預約狀態與虛擬介面一致；不因重複相關查詢產生重複關閉紀錄。

## 3.10 G｜跨功能事件與稽核

關聯事件觸發與館員管理操作稽核。

### FR-48 關聯事件觸發

- **來源**：SRC-48
- **功能規格**：無背景排程。**僅在操作與該任務有業務關聯時**，處理該範圍的到期狀態、點數恢復、候補失效或提醒。觸發範例與處理範圍以**下方關聯事件表**為共同驗收基準，不要求整站任意查詢都掃描所有預約。
- **驗收條件**：預約／館員／點數等相關畫面能在需要時取得最新正確狀態；不相關操作不無故改動其他資料或發提醒；同一事件重複觸發不重複處理。

### FR-49 館員稽核

- **來源**：SRC-49
- **功能規格**：館員成功的討論室／開放時間修改、報到、點數調整、提前結束、通知寄送／重試等操作，要保留操作時間、類型及相關對象。
- **驗收條件**：可查成功異動；共用館員身分無須區分個別員工帳號。

# 4. 非功能需求（Non-functional requirements）

本章分類來自共同業務來源的跨功能品質要求與共同假設。未定義的量化品質門檻不自行補充。

## 4.1 安全性／隱私（Security / Privacy）

### NFR-01 資料存取控制

- **來源**：SRC-02。
- **規格**：學生的私人預約、邀請、候補、點數與停權資訊必須依目前選用身分隔離；公開空房查詢不得揭露其他學生個資。未授權操作必須在處理端拒絕，不能只依靠隱藏介面控制項。
- **驗收條件**：使用不同學號交叉讀取、變更其他人資料須被拒絕；公開查詢結果不揭露他人私人資料。

## 4.2 相容性／易用性（Compatibility / Usability）

### NFR-02 跨裝置瀏覽

- **來源**：SRC-50。
- **規格**：學生端及館員端主要功能應可在手機與電腦瀏覽器操作。
- **驗收條件**：兩組的部署網址均可於手機及電腦進行主要查詢、預約、報到與館員管理流程。

## 4.3 資料持久性（Persistence）

### NFR-03 成功結果持久保存

- **來源**：SRC-51；共同假設。
- **規格**：成功的預約、邀請／回覆、候補、報到／未到場、點數／停權、通知及設備控制狀態須妥善保存在資料庫，而非只保存在前端記憶體。
- **驗收條件**：重新整理、關閉再開啟頁面後，已成功的操作結果仍可查詢；兩組資料獨立。

## 4.4 可靠性／一致性（Reliability / Consistency）

### NFR-04 核心狀態與失敗處理

- **來源**：SRC-52、SRC-43。
- **規格**：核心業務失敗須顯示原因，不得宣稱成功；同一業務事件涉及的狀態、點數、候補及待寄送通知紀錄不可只更新其中一部分。Mock Mail 寄送失敗不得回退已完成的核心業務。
- **驗收條件**：無效輸入、衝突及競爭操作不留下部分成功結果；Mock Mail 寄送失敗不使已成功預約或管理操作回退。

## 4.5 可稽核性（Auditability）

### NFR-05 館員管理操作紀錄

- **來源**：SRC-49；共同假設。
- **規格**：館員成功修改房間／開放時間、報到、調整點數、提前結束、通知寄送／重試等行為，須記錄操作時間、類型和相關對象。使用共用館員身分，不要求區分個別館員帳號。
- **驗收條件**：各成功管理操作可查其操作類型、時間與相關對象。

## 4.6 事件處理冪等性（Idempotency）

### NFR-06 關聯更新與避免重複處理

- **來源**：SRC-48、SRC-44；共同假設。
- **規格**：到期檢查、點數恢復、候補失效與提醒，依有關聯的查詢／操作觸發，不採背景排程；相同事件反覆觸發不得重複處理或重複通知。
- **驗收條件**：相同業務操作的重複查詢不重複記點、不產生重複狀態轉換或相同通知；無關查詢不更動其他房間、學生或日期的資料。

## 4.7 尚未指定量化標準的品質要求

2026/11/05 需求來源未提供容量（Capacity）、負載擴充性（Scalability）、回應時間（Performance）、可用率（Availability）或獨立可維護性衡量（Maintainability）的數值。因此本版**不擅自制定**同時使用者上限、延遲上限、成功率或可用率門檻。若後續需新增，應先修訂共用需求來源並依審查、變更流程簽核。

# 5. 業務規則與狀態索引

本章集中整理預約、報到、違規點數、狀態轉換、通知與關聯事件，供 UML 與測試使用，正式限制以對應的 FR 和 SRC 為準。

## 5.1 預約共用規則速查

## 5.2 報到、記點、停權與恢復速查

| 需求 | 項目 | 核心限制 |
|---|---|---|
| FR-32／SRC-32 | 報到 | 開始起至開始後 +10 分鐘（含），須館員確認預約者本人到場。 |
| FR-33／SRC-33 | 未到場 | 超過開始後 10 分鐘仍未報到，於相關事件觸發時判定；恰好 +10 分鐘不算。 |
| FR-37／SRC-37 | 未到場記點 | 每筆未到場只記預約者 1 點，保留實際事件處理時間。 |
| FR-36／SRC-36 | 人工調整 | 館員以整數加／減點，需填原因；不能低於零；減點按 FIFO。 |
| FR-38／SRC-38 | 停權啟動 | 新增點數後達 3 點以上且尚未停權，啟動 7 天停權；純查詢不重新啟動。 |
| FR-39／SRC-39 | 停權更新與解除 | 停權期間新增點數仍達 3 點時，結束期限取原期限和加點後 7 天較晚者；人工減至低於 3 點可提前解除；自動恢復不提前解除。 |
| FR-40／SRC-40 | 自動恢復 | 每至少 7 天抵銷最早有效 1 點；下次恢復時間取「最早有效點時間＋7 天」與「前次自動恢復＋7 天」較晚者。 |
| FR-34／SRC-34 | 完成使用 | 館員可提前結束已報到預約；到期經相關事件更新；完成應關閉對應虛擬設備。 |

## 5.3 正式預約／邀請申請狀態轉換（SRC-20）

| 原狀態 | 事件 | 新狀態 | 依據 |
|---|---|---|---|
| 尚未建立 | 無受邀者、規則通過、無時段衝突 | 已預約 | SRC-08 |
| 尚未建立 | 有受邀者 | 待確認 | SRC-21～22 |
| 待確認 | 全部接受、全部成立規則通過、房間可用 | 已預約 | SRC-23 |
| 待確認 | 全部接受、只有房間衝突、預約者同意候補 | 已取消（原因：轉候補；另建立候補中申請） | SRC-23、27 |
| 待確認 | 拒絕、逾期、其他成立檢查失敗或預約者取消 | 已取消 | SRC-11、22～24 |
| 已預約 | 合法修改 | 已預約（更新資料） | SRC-10、18 |
| 已預約 | 合法取消 | 已取消 | SRC-11、18 |
| 已預約 | 館員確認報到 | 已報到 | SRC-32 |
| 已預約 | 超過報到寬限仍未報到 | 未到場 | SRC-33、37 |

## 5.4 候補申請狀態轉換（SRC-26～31）

| 原狀態 | 事件 | 新狀態 |
|---|---|---|
| 尚未建立 | 學生直接申請、或多人邀請全員接受後轉候補 | 候補中 |
| 候補中 | 同房間正式預約取消後，重新檢查成功 | 已遞補（另建立「已預約」） |
| 候補中 | 預約者退出 | 已退出 |
| 候補中 | 起始時間已到仍未遞補 | 已失效 |
| 候補中 | 本輪因衝突、停權、額度等暫時未通過 | 候補中（保留本輪原因） |

**注意**：候補名單以房間而非原被衝突的預約為單位；僅「已預約整筆成功取消」才依序檢查同房間候補；修改、未到場、完成及提前結束不觸發候補遞補（SRC-26～31）。

## 5.5 關聯事件觸發與範圍（SRC-48）

| 使用者觸發的操作 | 應檢查／觸發的相關業務 | 不應擴大的範圍 |
|---|---|---|
| 學生查詢特定房間時段／嘗試預約 | 該房間、指定時段影響空閒與可用額度的逾期未到場／已完成狀態；必要時更新相關候補過期狀態 | 不掃描所有房間、不產生無關預約的提醒 |
| 學生查看／回覆自己的邀請 | 該邀請是否逾期、該筆待確認預約是否可成立或轉候補 | 不更動其他學生的無關邀請 |
| 學生查看自己的候補／館員查看某房間候補 | 所查候補是否已過開始時間，必要時標為已失效並建立相關通知 | 不替其他房間做遞補；過期本身不觸發遞補 |
| 學生取消一筆「已預約」 | 該預約取消及**同房間候補**遞補、受影響通知 | 不處理其他房間候補；修改或取消待確認不觸發遞補 |
| 館員查詢**即將開始**的預約 | 查詢範圍內符合 30 分鐘門檻的開始提醒及其 Mail 通知 | 不產生已開始／無關時段的提醒 |
| 館員查詢**使用中／即將結束**的預約 | 查詢範圍內符合 10 分鐘門檻的結束提醒，及已到期之已報到預約完成與設備關閉 | 不產生其他日期、房間的結束提醒 |
| 館員查詢待報到名單／辦理報到 | 查詢範圍內超過 10 分鐘仍未報到的預約判定、記點及其通知 | 不對未超時者記點 |
| 學生查自己的點數或申請需要資格檢查的預約；館員查／調整某學生違規 | **該名學生**到期點數恢復、停權解除或資格檢查 | 不補算全校學生點數 |
| 預約者要求啟用虛擬設備／館員提前結束／查詢該房使用狀況 | 該筆預約是否仍可使用、是否到期完成，及對應設備狀態同步 | 不隨機改動其他房間設備 |
| 館員在通知中心執行寄送／重試 | 處理所選待寄送或失敗通知，成功者不得重送；**不額外掃描全部預約產生提醒** | 不以「寄送」當作全系統狀態更新排程 |

## 5.6 通知事件與收件對照（SRC-41）

開始與結束提醒僅寄送給預約者，且相同業務事件＋通知類型＋收件者不得重複建立通知（SRC-42～44）。

| 事件 | 收件人 | 通知重點 |
|---|---|---|
| 預約成立、修改、已成立預約取消 | 預約者及該筆已接受參與者 | 房間、時間、結果／變動 |
| 發出邀請 | 各受邀者 | 邀請資訊與待回覆狀態 |
| 邀請遭拒、待確認逾期／成立失敗 | 預約者及所有相關受邀者 | 失敗或取消原因 |
| **預約者主動取消待確認** | **所有受邀者**（另通知預約者） | 邀請／預約已取消，不可再回覆 |
| 全員同意但遇衝突而轉候補 | 預約者及全部已接受參與者 | 尚未預約成功、已轉為候補 |
| 候補成功遞補 | 候補預約者及該筆已確認參與者 | 正式預約已成立 |
| 候補開始時間已到而失效 | 候補預約者（多人時含已確認參與者） | 候補失效 |
| 判定未到場、館員調整點數、自動恢復、停權啟動／延長／解除 | 被記點／停權的學生 | 點數或停權變化 |
| 即將開始／即將結束提醒 | **僅預約者** | 時間與討論室 |
