# 共同假設

## 一、技術與模擬環境

| 項目 | 共同前提 | 說明／範圍 |
|---|---|---|
| 語言 | TypeScript | 提供型別檢查，兩組各自撰寫程式。 |
| 前端／後端 | Next.js（前後端同專案）＋ Tailwind CSS | 不強制兩組使用相同元件、API 或程式架構。 |
| 資料庫 | PostgreSQL（Neon 免費方案）＋ Prisma | 兩組分別使用獨立資料庫，資料表可由各組依 SRS／Stories／UML 設計。免費方案每個專案提供 1 GB 儲存空間及每月 100 CU-hours，閒置 5 分鐘後會縮至零。 |
| 部署 | Vercel Hobby 免費方案 | 以 GitHub 連接各組應用程式，分別部署與提供網址。Hobby 僅供非商業用途且有用量上限；到達上限時服務可能暫停，Runtime Log 只保留 1 小時。 |
| Mail | **Mock Mail Adapter** | 模擬待寄送、成功、失敗及重試，記錄收件者與通知內容，**不真的寄出 Email**。 |
| 排程 | **不使用背景排程／定時工作** | 這是為降低免費方案用量及實作複雜度所做的專案決定。到期狀態與提醒須由指定查詢或操作觸發，不要求於時限到達自動執行。 |
| 虛擬設備 | 使用系統內的虛擬設備介面 | 僅模擬主要預約系統與外部設備的互動，不連接、不控制真實硬體。 |

### 免費方案限制與因應

| 限制／風險 | 專案因應 |
|---|---|
| Vercel Hobby 達到免費用量上限時可能暫停服務，且 Runtime Log 僅短期保留 | 本專案只作課程展示及測試；部署期間查看用量，避免高頻輪詢及長時間函式。需長期保存的館員操作、通知及錯誤結果寫入 PostgreSQL，不依賴 Runtime Log。 |
| Neon 免費方案每組資料庫有儲存及運算額度，閒置後縮至零可能使下一次連線需要喚醒 | 兩組使用獨立專案並分別監看用量；查詢只取必要欄位、列表採分頁、常用查詢欄位建立索引，避免不必要的全表掃描。 |
| 免費方案內容可能調整，且不提供正式服務等級保證 | 部署前重新核對官方限制；若限制不足，先縮減測試資料或展示流量，不自行改變業務規則。 |

> 免費方案限制依 2026-11-11 的 [Vercel Hobby 官方文件](https://vercel.com/docs/plans/hobby) 與 [Neon Plans 官方文件](https://neon.com/docs/introduction/plans) 整理。

## 二、身分、資料來源與展示限制

| 項目 | 共同前提 | 說明／範圍 |
|---|---|---|
| 身分驗證範圍 | **不實作正式身分認證** | 不使用密碼，學生輸入已建檔學號、使用者選「館員」，操作行為見 SRC-01。 |
| 館員資料 | 共用單一館員身分 | 不建立個別館員帳號；成功的操作須依 SRC-49 紀錄操作時間與類型。 |
| 初始測試資料 | 每組自行設計可供測試的學生、討論室與開放時間 | 不限定固定筆數、學號或房間名稱，但須能驗證共用規則與邊界。 |
| 預估驗證規模 | 50 筆學生、10 間討論室、累積 1,000 筆預約紀錄 | 作為資料表、索引、查詢與列表分頁的最低驗證資料量；詳細驗收方式見 SRC-53。 |

## 三、兩組的分工隔離

| 項目 | 共同前提 | 說明／範圍 |
|---|---|---|
| Repo | 同一個 Git repo | `waterfall/app/` 與 `agile/app/` 分別存放兩組程式。 |
| 部署 | 兩個獨立 Vercel 專案 | 各自的 Root Directory 指向對應的 `app/`。 |
| 資料庫 | 各有一個資料庫 | 測試資料可不同，但需能驗收同一份共用需求。 |
