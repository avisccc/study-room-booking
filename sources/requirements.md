# 需求來源清單

## 1. 文件目的與系統概觀

### 1.1 共同目標

本系統以網頁提供學生查詢討論室空閒狀況、建立／管理預約、多人邀請及候補；館員管理房間與開放時間、辦理報到及處理違規。系統保存可查詢的操作與狀態紀錄，透過模擬 Mail 與虛擬設備呈現通知及智慧控制的互動。

本文件是**瀑布組與敏捷組共用的業務需求來源**：統一功能、約束及可驗收結果。瀑布組使用 `FR-xx`／`NFR-xx`、敏捷組使用 `US-xx` 編號，各項須追溯至本文件的 `SRC-xx`。

### 1.2 功能地圖

| 模組 | 使用者 | 核心能力 | 需求編號 |
|---|---|---|---|
| F01 身分與操作範圍 | 學生、館員 | 模擬身分選擇、資料存取權限 | SRC-01～02 |
| F02 討論室查詢與管理 | 學生、館員 | 房間搜尋、開放時間、館員管理 | SRC-03～07 |
| F03 一般預約與共用規則 | 學生 | 預約、修改、取消、限制、狀態 | SRC-08～20 |

| F05 候補與自動遞補 | 學生 | 房間共用候補、多人成員、遞補 | SRC-26～31 |
| F06 報到與使用結束 | 館員、系統 | 報到、未到場、完成 | SRC-32～34 |

### 1.3 基本術語定義

| 術語 | 意義 |
|---|---|
| **預約者** | 一筆預約唯一的負責學生；預約額度、報到責任與未到場點數都歸屬此人。 |
| **受邀者／參與者** | 受邀者尚可接受或拒絕；接受後成為參與者。參與者不分擔預約者的時數、筆數及未到場記點。 |
| **待確認** | 含受邀者且尚未全員接受的預約申請；不占用房間或預約額度。 |
| **有效預約** | 已成立且狀態為「已預約」或「已報到」、尚未結束的預約；占用房間時段及預約者額度。 |
| **候補申請** | 針對特定討論室與起訖時間提出的等候資格；與已成立預約的狀態分開表示，候補中不占用房間或額度。可保留已確認的多人參與名單。 |
| **事件觸發更新** | 不依賴背景排程；僅在與對應業務相關的查詢或操作時，檢查並更新其涉及的到期狀態／通知。 |
| **時間基準** | 所有業務日期、整點、日界與提醒視窗均以 `Asia/Taipei` 解讀；是否到期以系統伺服器當下時間判斷。 |

## 2. F01｜身分與操作範圍

**功能目的：** 以簡化身分選擇模擬學生與館員的不同工作流程。

| 編號 | 功能與業務規則 | 驗收重點 |
|---|---|---|
| **SRC-01** 身分選擇 | 使用者可輸入**已建檔學號**選擇學生身分，或選用**共用館員身分**；可返回入口重新選擇。無密碼及正式身分驗證。 | 未建檔學號不可進入學生端；不同角色顯示對應功能，切換後依新選用身分操作。 |
| **SRC-02** 操作權限 | 學生只能查看／處理其目前身分所屬的預約、邀請、候補、點數及停權資訊；能對邀請做出回覆，但不能替其他預約者修改或取消預約。館員可查看預約與違規資料並執行館員管理事項。 | 不得以學生端讀取或修改無關學生的私人資料；公開空閒時段不揭露其他學生個資；不只隱藏按鈕，也要拒絕未授權操作。 |

## 3. F02｜討論室查詢與館員管理

**功能目的：** 學生找得到適合且可用的房間；館員可管理房間、開放時段及使用情形。

| 編號 | 功能與業務規則 | 驗收重點 |
|---|---|---|
| **SRC-03** 房間與時段查詢 | 學生可查看可用討論室、開放時間及依日期、起訖時段查詢使用狀況。 | 可區分指定時段可預約與不可預約；已停用房間不得提供新預約。 |
| **SRC-04** 條件搜尋 | 學生可依房間固定設備標籤、容納人數，結合日期／時段尋找符合條件的討論室。 | 結果符合所選標籤、容量及時段條件，不把不可使用的房間列為可預約。 |
| **SRC-05** 房間管理 | 館員可新增、修改及停用討論室，管理名稱、固定設備標籤與**正整數**容量；不得刪除歷史預約。有尚未結束的有效預約時不能停用；縮小容量若不足容納任何既有有效預約的預約者與參與者，須拒絕。 | 有效預約不因房間管理而被破壞；待確認申請不阻止修改，但最終成立時須依最新容量與房間狀態重驗；館員能查看停用房間歷史。 |
| **SRC-06** 開放時間管理 | 館員可設定或修改各房間開放時間。預約成立／修改後必須完整落在對應房間的開放時間內；若變更會使既有有效預約不受涵蓋，須拒絕。 | 更改開放時間不破壞有效預約；尚未成立的待確認／候補在成立時依最新規則驗證。 |
| **SRC-07** 館員查詢預約 | 館員可依日期、討論室或時段查看預約者、參與者及預約狀態，包含當日／即將開始及使用中的預約資訊。 | 查詢內容正確，並依 SRC-48 對**查詢範圍內相關預約**處理到期狀態或提醒，不影響無關房間與日期。 |

## 4. F03｜一般預約與共用規則

**功能目的：** 以同一組預約規則支援單人、多人的成立與修改，以及候補成功遞補後的預約。

### 4.1 預約操作

| 編號 | 功能與業務規則 | 驗收重點 |
|---|---|---|
| **SRC-08** 建立預約 | 學生指定討論室、開始與結束時間，並可選擇邀請其他學生。**無受邀者**且通過共用預約規則者直接成為「已預約」；有受邀者依 F04 處理。房間時段衝突時可依 F05 選擇候補。每筆正式成立的預約恰有一位預約者。 | 不符合規則者不得直接占用時段；成立後可查到正確房間、時間、預約者與狀態。 |
| **SRC-09** 我的紀錄 | 學生可查詢自己作為預約者、受邀者或參與者的相關預約與邀請，及自己提出的候補狀態；至少呈現房間、時間、參與名單與狀態。 | 歷史資料保留且可依目前選用身分查詢；不顯示無關學生的私人紀錄。 |
| **SRC-10** 修改預約 | 只有預約者可修改**已預約**的討論室、開始或結束時間，參與名單不變；**待確認**不可直接修改，須取消並重新建立。修改須符合 SRC-18 並依新內容重驗所有適用規則；計算自身額度時排除原預約。**修改不觸發候補遞補，候補名單也不因個別預約修改而重建**（以討論室為單位，見 F05）。 | 修改成功後資料及通知一致；不符合條件時原預約維持不變；不會錯誤清除其他學生的房間候補。 |
| **SRC-11** 取消預約 | 只有預約者可取消自己的「待確認」或「已預約」預約，取消後保留歷史且不可復原。待確認可於開始前取消；已預約須符合 SRC-18。**待確認被預約者取消時，所有受邀者均收到取消通知**，未回覆邀請即結束；已預約整筆取消才依 F05 檢查候補。 | 取消後狀態正確、沒有部分取消；所有受邀者均有對應待寄送通知，已接受者也包含在內；只有符合條件的已預約取消會啟動遞補。 |

### 4.2 共用預約規則（單一權威定義）

以下條件適用於**建立、修改、全員接受而成立、候補遞補**等對應階段；待確認與候補中不提前占用額度。後續模組僅引用本節，不另訂不同數值。

| 編號 | 規則 | 驗收重點 |
|---|---|---|
| **SRC-12** 整點與時長 | 開始、結束時間**均須為整點**，每筆時長限 **1、2、3 或 4 小時**，不可為小數小時或超過 4 小時。 | 如 10:00–11:00、10:00–14:00 合法；10:30–11:30、10:00–11:30、10:00–15:00 拒絕。 |
| **SRC-13** 每日時數 | 每位學生以**預約者**身分持有的有效預約，按 `Asia/Taipei` 每個當地日期各自計算，不得超過 **8 小時／日**；跨午夜按各日實際占用時數拆分，參與他人預約不占自己的額度。 | 新增、修改與成立時，各受影響日期都不超標；修改不重複計算原預約。 |
| **SRC-14** 有效筆數 | 每位預約者最多同時持有 **10 筆**有效預約；待確認、候補中及參與他人預約均不計入。 | 已有 10 筆時第 11 筆不得成立；修改既有一筆不算新增。 |
| **SRC-15** 房間衝突 | 同房間有效預約的時間不可重疊；時間視為**左閉右開區間**，前筆結束時間等於後筆開始時間不衝突。**不同房間的重疊預約允許同一學生持有**，仍受其他額度限制。 | 同房同時段競爭最多一筆成功且不可留下部分結果；不同房間同時段不因「同一學生」而直接拒絕。 |
| **SRC-16** 停權資格 | 停權中的學生不可作為預約者使新預約成立或遞補；可接受他人邀請並作為參與者。既有已成立預約仍可查看；參與者不取得取消、修改、報到責任或設備啟用權。 | 成立／遞補時檢查最新停權狀態；不把停權錯誤套用到受邀者的接受資格。 |
| **SRC-17** 時間與房間有效性 | 開始須**晚於當下伺服器時間**，結束晚於開始；房間可用，且整段預約位於開放時間內。 | 不接受已到達或過去的開始時間；跨日依相關日期的開放時間完整檢查。 |
| **SRC-18** 修改與取消期限 | 「已預約」僅可在距**原開始時間至少 3 小時**時修改或取消；修改後新開始時間也須距現在至少 3 小時。待確認僅可在開始前取消。 | 恰好 3 小時允許已預約修改／取消，少於 3 小時拒絕；已開始者不能修改／取消。 |
| **SRC-19** 額度與占用定義 | 只有尚未結束的「已預約」／「已報到」屬有效預約，占用房間時段及預約者的 SRC-13／14 額度。「待確認」、「已取消」、「已完成」、「未到場」及候補中不占用。 | 評估空房與額度前，僅處理本次查詢／操作相關的到期狀態（SRC-48）；狀態變更後不殘留錯誤占用。 |
| **SRC-20** 預約狀態 | 正式預約／邀請申請的狀態限：「**待確認、已預約、已報到、已取消、已完成、未到場**」。每筆同時只有一種狀態，保留變動時間與原因；允許的轉換見第 12 節。**候補狀態另由 F05 管理，不額外混入此六種預約狀態**。 | 不可無故跳轉、重複報到或復原已取消預約；相關記錄能反映歷史。 |

## 5. F04｜多人預約與邀請

**功能目的：** 預約者可邀請已建檔學生，待全員確認後才成立預約；若僅遇房間衝突且預約者同意候補，則可保留同一批已確認參與者進入候補。

| 編號 | 功能與業務規則 | 驗收重點 |
|---|---|---|
| **SRC-21** 發送邀請 | 預約者可透過已建檔學生的**學號或 Email** 邀請他人；不得邀請自己或重複邀請同一學生。建立前核對受邀者存在、房間、時段、預約者停權資格及容量；成功後建立邀請及通知。可在提出時一併表達衝突時是否願意候補。 | 受邀名單無重複；有有效邀請及收件記錄；尚未全員回覆不直接占房。 |
| **SRC-22** 待確認階段 | 含受邀者的申請在全部接受前狀態為「待確認」，參與名單與房間／時段固定、不直接編修，且不占有效額度及房間。若到達預約開始仍未全員確認，於相關事件觸發時取消申請、結束邀請並通知。 | 未回覆時不可誤判已成立；過期後不可再接受或成立。 |
| **SRC-23** 接受與成立 | 每位受邀者可在開始前接受自己的未回覆邀請，一次有效回覆不得重複。全員接受後，依最新房間、容量、時間、預約者停權與 F03 共用規則檢查：**可預約則成立**；**僅房間時段衝突且已同意候補則轉入 F05**；其他不符合條件或未同意候補者取消申請，保留原因並通知。 | 只剩一人未回覆仍不成立；全部接受後不能同時產生正式預約與候補；轉候補不占房，後續遞補保留已接受的參與名單。 |
| **SRC-24** 拒絕與取消 | 任何受邀者在待確認時拒絕，整筆申請即取消；尚未回覆邀請一併結束，記錄拒絕者、時間與原因並通知相關人。預約者主動取消待確認者按 SRC-11。 | 被取消的邀請不得再接受；不產生有效預約或候補。 |
| **SRC-25** 人數與容量 | 預約者加上全部**不重複受邀者**不得超過房間正整數容量；建立邀請時先檢查，全員接受／候補成功遞補時依最新容量重驗。 | 超額邀請立即拒絕；容量後來不足不得成立／遞補；已成立預約受 SRC-05 保護。 |

## 6. F05｜候補與自動遞補

**功能目的：** 候補名單**以討論室為單位**，依加入時間排序，一次取消可能讓多筆不衝突候補依序成立。

| 編號 | 功能與業務規則 | 驗收重點 |
|---|---|---|
| **SRC-26** 候補申請 | 當指定房間與時段和至少一筆**有效預約**實際重疊時，學生可選擇提出候補，也可放棄。申請記錄其房間、完整起訖時間、預約者、參與名單與加入時間；候補中不占房間、每日時數或有效筆數。 | 只有實際正長度重疊才可加入；與相鄰時段僅接觸端點不算衝突；候補時段仍須符合整點、1～4 小時、未來時間及開放時間。 |
| **SRC-27** 多人候補 | **多人預約可以候補，但必須所有受邀者都已接受後才正式排入候補名單。** 發起時可預先選擇願意候補；待確認期間只保留邀請申請、不建立候補資格。全員接受時若只有房間衝突，將待確認申請結案為「已取消（轉候補）」並建立帶有**同一預約者與已接受參與者**的候補申請；若直接有空房則成立預約。 | 任一邀請未回覆／拒絕都不加入候補；轉候補後不占房，受邀者確認結果保留；遞補成功時不得把多人候補變成單人預約。 |
| **SRC-28** 名單與順序 | 每間討論室共用候補名單，依加入時間先後處理，不綁定某筆原始預約。不同申請可有不同完整起訖時間；同一預約者不可重複加入**同房間、相同起訖時間**的候補。 | 名單與時間、成員可查；修改其他人的預約不會重建或清空該房候補名單。 |
| **SRC-29** 候補退出 | 候補預約者可在遞補前退出自己的候補申請；退出後不再參與遞補，保留候補歷史。 | 不允許替別人退出；狀態為「已退出」且不占房間／額度。 |
| **SRC-30** 取消觸發遞補 | **同房間任一筆「已預約」正式預約整筆成功取消**時，依加入順序依序檢查每一筆候補：其**完整時段**須完全空閒，預約者與全部既定參與者須符合 F03、F04 的適用限制。每成功一筆即產生一筆新的「已預約」，並以最新占用狀況繼續檢查後續候補；**同一次取消可遞補多筆彼此不衝突的候補**。不得裁切候補時段。 | 依序、整段、逐筆重驗；單人候補生成單人預約，多人候補保留已接受參與者；一次取消可能有零筆、一筆或多筆成功，不產生雙重占用。 |
| **SRC-31** 遞補失敗與結案 | 遞補時因房間仍衝突、預約者停權、額度或其他暫時不符條件者，記錄原因、跳過並**保留候補中**，供下次相關取消事件重試；開始時間已到、主動退出或成功遞補者則結案，狀態分別為「已失效」、「已退出」、「已遞補」。**原預約修改、未到場、正常完成或館員提前結束均不觸發遞補**。 | 一人失敗不阻止後續者；過期者不再遞補；候補結果有可查狀態與原因，成功者不重複成立。 |

> **多人候補的狀態說明：** 邀請申請有自己的「待確認／已取消」等預約狀態；轉候補後由**候補申請**保存成員與「候補中」資格；遞補成功才建立新的有效預約。兩組可以自行決定資料實體如何實現，但外部可觀察行為必須一致。

## 7. F06｜報到與使用結束

**功能目的：** 以預約者本人到場作為報到依據，明確區分成功使用、未到場與完成使用。

| 編號 | 功能與業務規則 | 驗收重點 |
|---|---|---|
| **SRC-32** 報到 | 館員可在預約開始起至**開始後 10 分鐘（含）**，確認預約者本人到場，替一筆「已預約」辦理**一次**報到，狀態改為「已報到」並記錄時間。參與者是否到場不影響報到，但不能代替預約者。 | 恰好 +10 分鐘可報到；開始前、超過 +10 分鐘、只有參與者到場或已報到時不得再報到。 |
| **SRC-33** 未到場 | 「已預約」且超過開始後 **10 分鐘**仍未報到，於相關業務查詢或操作時標為「未到場」，並由 F07 對**預約者**記點一次。 | 恰好 +10 分鐘不判未到場，超過才判定；不得重複記點；此事件與記點結果一致。 |
| **SRC-34** 完成使用 | 館員可替已報到的預約提前結束；或於預約到達結束時間後，由相關查詢／操作觸發完成處理。狀態變為「已完成」，並依 F09 關閉設備。 | 正常到期與提前結束均只完成一次；完成後不得再啟用設備。 |

## 8. F07｜點數、違規與停權

**功能目的：** 對未到場與館員認定的違規記點、管理停權並提供學生查詢。

| 編號 | 功能與業務規則 | 驗收重點 |
|---|---|---|
| **SRC-35** 我的點數 | 學生可查看自己的目前有效點數與停權狀態；停權時顯示結束時間。 | 相關查詢先依 SRC-48 補算本人應恢復的點數及到期停權，顯示與最新結果一致。 |
| **SRC-36** 館員違規處理 | 館員可查看未到場紀錄、點數與停權，並**以整數**手動加點或減點，必須提供原因。每次異動保存調整前後點數、差額、時間及原因；減點不得超過現有點數，也不能低於零。減點依 SRC-40 抵銷最早尚有效點數，並按 SRC-39 更新停權。 | 正確記錄可追蹤異動；加點／減點及停權結果同步一致；不合法減點拒絕。 |
| **SRC-37** 未到場記點 | 每筆預約判定未到場時，只有**預約者增加 1 點**；參與者不記點。每個新增點數保留發生時間，採實際處理事件的伺服器時間而非回填截止時間。 | 同一筆未到場只加一次；失敗不得只改狀態或只加點。 |
| **SRC-38** 停權啟動 | 新增點數事件（未到場或館員加點）使目前點數達 **3 點以上**且當下未停權時，啟動一筆新的 **7 天停權**並記錄起訖及原因；僅查詢既有 3 點以上而沒有新加點，不得重新啟動。 | 2→3 點啟動；已過期且分數仍為 3 點時，純查詢不重啟。 |
| **SRC-39** 停權更新／解除 | 停權期間新加點且更新後仍達 3 點時，結束時間延至**既有期限與此次加點後 7 天之較晚者**；館員手動減點至低於 3 點可立即提前解禁。到期即解除；**自動恢復點數不提前結束現有停權**。 | 期間加點延長不縮短；手動減點與自然到期結果不同，不能混淆。 |
| **SRC-40** 點數自動恢復 | 未到場及館員加點按**每 1 點一筆**保存；每隔至少 **7 天**最多自動抵銷最早未抵銷的 **1 點**。下次恢復時間為「最早未抵銷記點時間＋7 天」與「前次自動恢復時間＋7 天」的較晚者（沒有前次時只用第一項）；手動減點採 FIFO。相關操作時補算所有已到期恢復；清零後新記點重新起算。 | 不會在不足 7 天間隔內連續自動扣兩點；點數不低於零；先舊後新，且能測試累積到期補算。 |

## 9. F08｜通知與提醒（Mock Mail）

**功能目的：** 學生收到與自己相關的預約／違規通知；館員可查看及重試通知。**不發送真實 Email**，事件、收件者及結果仍必須可查。

| 編號 | 功能與業務規則 | 驗收重點 |
|---|---|---|
| **SRC-41** 事件通知 | 系統應為下表所列的實際業務事件建立通知，收件人及訊息類型依事件決定；事件發生與通知建立一致記錄。邀請在系統介面接受／拒絕，Mail 僅用來告知，不能透過回信直接操作預約。 | 相關事件有正確收件人及通知內容；同一次全員接受不因「邀請確認完成」與「預約成立」重複發成功通知。 |
| **SRC-42** 開始／結束提醒 | **提醒僅寄給該筆預約的預約者**。館員查詢「接下來／即將開始的預約」時，對**已預約、尚未開始且距開始 ≤30 分鐘**者產生開始提醒並嘗試寄送；館員查詢「使用中／即將結束」時，對**已預約或已報到、尚未結束且距結束 ≤10 分鐘**者產生結束提醒並嘗試寄送。相同預約每種提醒最多一次，修改時間後不重發同種類提醒。 | 恰好 30／10 分鐘符合；已開始不寄開始提醒、已結束不寄結束提醒；受邀者／參與者不收到這兩種提醒；無關頁面不觸發。 |
| **SRC-43** 模擬寄送與重試 | 使用 `sources/assumptions.md` 的 Mock Mail Adapter 保留「待寄送、成功、失敗」狀態及收件者、事件、類型、建立／嘗試時間、失敗原因。事件發生的相關操作應嘗試模擬寄送；館員另可主動處理待寄送與失敗通知並重試，**成功者不再寄送**。Mock 失敗不回退已成功的預約、邀請、候補、點數或設備操作。 | 可展示成功、失敗、重試；通知結果與核心業務結果互不混淆。 |
| **SRC-44** 通知去重 | 對**同一業務事件＋通知類型＋收件者**不得建立或成功寄送重複通知；不同事件（如兩次手動加點）仍可各自通知。 | 重複觸發相關查詢不寄出第二封同提醒；失敗重試使用原紀錄而非新增第二份通知。 |

**SRC-41 事件與寄收件對照（本表為唯一寄收件規則）：**

| 事件 | 收件人 | 通知重點 |
|---|---|---|
| 預約成立、修改、已成立預約取消 | 預約者及該筆已接受參與者 | 房間、時間、結果／變動 |
| 發出邀請 | 各受邀者 | 邀請資訊與待回覆狀態 |
| 邀請遭拒、待確認逾期／成立失敗 | 預約者及所有相關受邀者 | 失敗或取消原因 |
| **預約者主動取消待確認** | **所有受邀者**（另通知預約者） | 邀請／預約已取消，不可再回覆 |
| 全員同意但遇衝突而轉候補 | 預約者及全部已接受參與者 | 尚未預約成功、已轉為候補 |
| 候補成功遞補 | 候補預約者及該筆已確認參與者 | 正式預約已成立 |
| 候補開始時間已到而失效 | 候補預約者（多人時含已確認參與者） | 候補失效 |
| 判定未到場、館員調整點數、自動恢復、停權啟動／延長／解除 | 被記點／停權的學生 | 點數或停權變化 |
| 即將開始／即將結束提醒 | **僅預約者** | 時間與討論室 |

> 「通知建立」與「Mock 寄送」是不同結果：業務操作形成通知紀錄，由相關業務操作依 SRC-48 的**關聯事件**嘗試模擬寄送；無關頁面或全站瀏覽不應批次產生提醒。通知中心提供館員手動補寄／重試入口。

## 10. F09｜智慧控制與虛擬設備

**功能目的：** 系統與獨立的虛擬設備介面交換控制命令及狀態，模擬討論室智慧管理；**不連接真實硬體**。

| 編號 | 功能與業務規則 | 驗收重點 |
|---|---|---|
| **SRC-45** 虛擬設備介面 | 提供與主要預約系統**可互動、可通訊**的獨立虛擬控制介面，代表討論室的**門禁、燈具、空調或電源等設備**。介面能呈現對應房間與設備的目前狀態、收到的控制動作及結果；兩組可自行選擇內部通訊方式與呈現方式，不需要真實硬體。 | 從主要預約系統發出操作後，虛擬介面反映該房間相應設備的控制結果；可觀察狀態而非僅在預約頁上顯示一段成功文字。 |
| **SRC-46** 啟用控制 | 只有**已報到**預約的預約者可在其有效使用期間透過主要系統要求啟用對應房間虛擬設備；其他參與者或尚未報到、取消、完成、未到場的預約不得啟用。 | 有權操作時能對虛擬介面送出啟用並顯示狀態；無權／無效狀態操作拒絕，不會改變設備。 |
| **SRC-47** 結束關閉 | 預約完成（到期或館員提前結束）或判定未到場時，主要系統應使對應房間虛擬設備處於**關閉／停用**狀態並保留觸發原因與時間；同一狀態無須重複轉換。 | 設備不在預約結束後保持啟用；可核對主系統預約狀態與虛擬介面一致；不因重複相關查詢產生重複關閉紀錄。 |

> 門禁、燈具、空調與電源是**可模擬的設備類型範例**，本文件不規定設備的類型，也不指定單一設備控制協定，應展示**主系統與所選虛擬設備控制項的互動**，且開啟／關閉及預約狀態具一致關係。

| 館員查詢**使用中／即將結束**的預約 | 查詢範圍內符合 10 分鐘門檻的結束提醒，及已到期之已報到預約完成與設備關閉 | 不產生其他日期、房間的結束提醒 |
| 館員查詢待報到名單／辦理報到 | 查詢範圍內超過 10 分鐘仍未報到的預約判定、記點及其通知 | 不對未超時者記點 |
| 學生查自己的點數或申請需要資格檢查的預約；館員查／調整某學生違規 | **該名學生**到期點數恢復、停權解除或資格檢查 | 不補算全校學生點數 |
| 預約者要求啟用虛擬設備／館員提前結束／查詢該房使用狀況 | 該筆預約是否仍可使用、是否到期完成，及對應設備狀態同步 | 不隨機改動其他房間設備 |
| 館員在通知中心執行寄送／重試 | 處理所選待寄送或失敗通知，成功者不得重送；**不額外掃描全部預約產生提醒** | 不以「寄送」當作全系統狀態更新排程 |

> 當同一操作同時涉及數個有關業務（例如「預約房間」須先檢查該房逾期狀態，然後判斷衝突），可在同一次操作完成必要更新；**重要的是有因果關聯且保持一致性**，而不是將事件處理綁定某一特定頁面或 API 名稱。
